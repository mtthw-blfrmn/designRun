# ReactBits

ReactBits is a collection of copyable animated React components and visual treatments. Use it to study a behavior or accelerate a bounded implementation—not as a default aesthetic, dependency, or substitute for product judgment.

## Use when

- The team needs a concrete reference for text reveals, backgrounds, cards, loaders, cursors, or small interactive treatments.
- A coded example can help test whether an effect serves the product before building a local primitive.
- The selected component can be inspected, adapted, and owned by the project.

## Do not use when

- The treatment would make an operational product feel like a demo reel.
- A component obscures state, harms readability, or consumes attention without adding meaning.
- The agent cannot identify its dependencies, license terms, performance cost, or reduced-motion behavior.

## Agent instructions

1. Start from the product need and relevant Taste or Inspiration evidence. Name the behavior being explored before opening ReactBits.
2. Select one exact component and the variant matching the project's language, type system, and styling approach. ReactBits offers JavaScript or TypeScript and CSS or Tailwind variants; do not introduce a second styling system for one effect.
3. Read the component source and dependency list before copying or running a CLI command. Prefer manual source adoption when it makes ownership and review clearer.
4. Place adopted code in the owning project's component boundary. Rename generic demo concepts to product semantics and replace hard-coded colors, spacing, radii, typography, durations, and easing with project tokens.
5. Remove demo-only controls, sample data, pointer-following effects, excessive glow, and unrelated dependencies.
6. Define loading, empty, error, focus, touch, reduced-motion, and small-screen behavior. A visually impressive default state is not a complete component.
7. Preserve license and attribution obligations. The official repository currently identifies its license as MIT plus Commons Clause; verify the current license before redistribution and do not package copied work as a competing component library.
8. Compare the adapted result to the original behavior and to the product's own Taste rules. Copy the underlying principle, not the reference's visual identity.
9. Keep provenance in the project decision or implementation notes: component name, official URL, date checked, changes made, and dependencies retained.

## Verification

- Run the exact adapted component in the target application rather than judging the gallery preview.
- Inspect console errors, dependency warnings, bundle impact, and production build output.
- Test keyboard navigation, screen-reader naming, contrast, text zoom, reduced motion, touch input, and responsive clipping.
- Stress long content, localization, slow data, repeated activation, and unmounting.
- Confirm removing the effect would not reveal missing product state or information architecture.

## Constraints

- ReactBits is source inspiration; copied code becomes project-owned code that must meet local standards.
- Do not use gallery popularity as evidence that a treatment is appropriate.
- Do not assume every example is accessible or production-ready.
- Recheck the official component page and repository license because components and installation methods change.
