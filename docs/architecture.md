# Architecture

designRun uses plain files so product context remains portable, diffable, auditable, and independent of one model or harness.

## System model

```text
Taste + Inspiration ──→ shared Design System
          │                      │
          └──────→ Project context + evidence
                                 │
                                 ├──→ decisions and requirements
                                 ├──→ prototypes and deliverables
                                 └──→ proven promotion candidates
                                              │
                                              └──→ Patterns / shared system
```

## Canonical and derived layers

Canonical sources live in `taste/`, `inspiration/`, `knowledge/`, `resources/`, `projects/`, `patterns/`, and `.agents/skills/`. The app reads `app/public/workspace-index.json`, generated by `npm run index`. Never edit that index by hand.

The local API saves Markdown back to canonical files. A save includes the file's previous modification time; if an agent or editor changed the source after it was opened, the app returns a conflict rather than overwriting newer work. Browser storage may preserve an unsaved draft, but it is never the saved source of truth.

Writes are restricted to known Markdown owners, reject symlinks and cross-origin browser mutations, cap payload size, and replace files atomically. Asset previews use a separate allowlist, exclude private source areas, cap size, and support byte ranges for video.

## Object model

- A Project is the top-level container for one product.
- A Deliverable is a concrete app, prototype, deck, export, or maintained artifact within a project.
- A deliverable folder lives at `projects/<project>/deliverables/<deliverable>/`; its `README.md` owns outcome, implementation boundary, source map, verification, and shipping boundary.
- Project documents include briefs, research, decisions, prototype notes, requirements, and operating records.
- Taste principles, references, skills, tools, assets, and shared system sources are first-class global objects.
- Inspiration media is evidence that helps agents form judgment; it remains attached to source-attributed reference records and is not offered for project reuse.
- Assets are reviewed, reusable project elements. Only files declared by an `asset-library/**/manifest.json` are included in the Assets index; raw intake and supporting contact sheets are excluded.
- To‑Dos are actionable work items in a source-backed JSON block.

## Why promotion is explicit

Copying every successful prototype into the shared system creates accidental standards. Promotion asks whether the problem recurs, which parts travel, which states and accessibility requirements are known, and when the pattern should not be used.

## The local control center

The browser app is the operational surface for the workspace, not a second product database. It discovers source files, provides hierarchy and search, edits Markdown, renders local assets, and creates context-aware handoffs to the agent harness. The agent and browser operate on the same project.

The development process watches canonical roots and rebuilds the derived index. The browser periodically checks that index and refreshes when the agent changes sources. Indexing skips generated, dependency, private, vendor, and source-intake directories; limits and additional ignored path prefixes live in `designrun.config.json` so a nested implementation repository cannot silently turn the control center into a code-search index.
