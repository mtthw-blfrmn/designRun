# Workflows

Ask naturally. Naming a repository skill is useful when you want its exact procedure.

| Workflow | Use it for | Durable result |
| --- | --- | --- |
| `project-setup` | Create and frame a product | Brief, decisions, research, and deliverable structure |
| `todo-extractor` | Turn messy sources into tasks | Triage-ready To‑Dos with source context |
| `research-synthesis` | Interviews, feedback, and evidence | Findings with provenance, limits, and implications |
| `product-decision` | Resolve a consequential choice | Recommendation or approved decision with tradeoffs |
| `product-requirements` | Turn direction into buildable behavior | Scope, states, requirements, and acceptance criteria |
| `user-flow` | Model a task, branch, or state system | Narrative or diagram with recovery paths |
| `product-prototype` | Explore a product direction through a working slice | Verified prototype and explicit learning question |
| `design-critique` | Review a real design or implementation | Prioritized, concrete revision direction |
| `design-to-code` | Implement a supplied design | Verified code in the named implementation repository |
| `component-polish` | Refine an already functional UI | State-complete, resilient, system-aligned implementation |
| `reference-capture` | Learn from an example | A specific lesson with provenance and transfer limits |
| `image-direction` | Create or refine product imagery | Inspected asset with placement, provenance, and limitations |
| `pattern-promotion` | Generalize proven project work | Reviewed shared pattern or an evidence gap |
| `workspace-audit` | Find drift, duplication, or privacy risk | Path-specific health report and safe fixes when requested |

## Prompt recipes

### New product

```text
Set up a new project called Atlas. It helps independent consultants see which client work is at risk. Shape the brief without inventing missing evidence.
```

### Product decision

```text
Use Atlas's brief and research to decide whether the first view should organize work by client, deadline, or risk. Compare credible alternatives and recommend one. Do not mark it approved until I confirm it.
```

### Critique

```text
Critique the Atlas onboarding prototype. Inspect the implementation and relevant references. Evaluate product intent and flow before visual craft, then give me the three highest-leverage revisions. Do not implement yet.
```

### Implementation

```text
Use the design-to-code workflow to implement the approved onboarding design in the repository recorded in Atlas deliverables. Match the source, complete relevant states, and verify the build and keyboard path.
```

### Promotion

```text
Review the progressive-disclosure behavior from Atlas as a candidate shared pattern. Promote only the reusable core if the evidence, state model, and accessibility behavior are sufficient.
```

The workspace itself is continuous. Work goes directly into the project, source document, or implementation repository that owns it.
