# Vercel project provisioning

## Observed behavior

A narrow centered sequence decomposes project setup into stacked task cards. A compact project summary preserves object identity; integration rows use direct actions; the next configuration area remains partially visible to communicate sequence.

## What works

One card owns one job, so technical setup feels bounded. The consistent reading axis, restrained borders, and direct object/action rows keep infrastructure work calm while the preview supplies identity.

## Principle to inherit

For sequential technical setup, keep the configured object visible, focus one task at a time, preserve completed context above, and hint at the next task below.

## Do not copy literally

Do not reproduce Vercel branding, provider rows, repository metadata, card dimensions, or the same card treatment when comparison or validation requires a richer surface.
