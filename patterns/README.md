# Patterns

Patterns are reviewed, cross-project learnings. They are not a gallery of every component ever built.

Add a pattern only when:

- it has been exercised in a real project or representative prototype;
- the problem recurs beyond that project;
- the reusable principle can be separated from project copy, brand, and data;
- important states, accessibility requirements, and tradeoffs are understood; and
- the pattern has an owner or a clear source.

Use `templates/pattern.md` and the `pattern-promotion` skill. A pattern may later become a token, component rule, motion rule, content rule, or implementation primitive.
